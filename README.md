# rick-morty-backend

Учебный проект: свой бекенд по мотивам [Rick and Morty API](https://rickandmortyapi.com/).

Данные персонажей хранятся в памяти (`src/data/characters.ts`) и сбрасываются при перезапуске сервера.

## Стек

- Node.js (версия в `.nvmrc`, `>=24.19.0 <25`)
- TypeScript, для запуска — `tsx`
- [Express](https://expressjs.com/) 5 — HTTP-сервер и роутинг
- `http-status-codes` — числовые коды ответов

## Скрипты

| Команда       | Описание                             |
| ------------- | ------------------------------------ |
| `npm run dev` | Сервер с перезапуском при изменениях |
| `npm start`   | Однократный запуск сервера           |

| Переменная | По умолчанию | Назначение        |
| ---------- | ------------ | ----------------- |
| `PORT`     | `3000`       | порт сервера      |
| `HOST`     | `localhost`  | хост в логе старта |

Базовый URL: `http://localhost:3000`.

## Структура приложения

```text
src/
├── server.ts                 # точка входа, listen()
├── app.ts                    # createApp(): middleware и маршруты
├── routes/                   # Express Router
├── controllers/              # HTTP: статус, JSON-ответ
├── services/                 # бизнес-логика и работа с хранилищем
├── middleware/               # лог запросов, 404, обработчик ошибок
├── data/characters.ts        # типы и in-memory массив
└── lib/                      # validate, HttpError, ошибки домена
```

Поток запроса: **маршрут → контроллер → сервис → данные**. Ошибки с кодом HTTP кидаются как `HttpError` и попадают в `errorHandler`.

Подключённые middleware:

- `express.json()` — разбор JSON-тела
- `requestLogger` — в консоль: `METHOD path status времямс`
- `notFoundHandler` — неизвестные пути
- `errorHandler` — `HttpError`, битый JSON (`Invalid JSON`), прочие сбои (`500`)

## Модель персонажа

| Поле       | Тип      | Правила                                                                               |
| ---------- | -------- | ------------------------------------------------------------------------------------- |
| `id`       | `string` | UUID, выдаёт сервер. В теле POST/PUT/PATCH не передаётся; в PATCH поле `id` запрещено |
| `name`     | `string` | непустая строка                                                                       |
| `status`   | `string` | `alive`, `dead` или `unknown`                                                         |
| `species`  | `string` | непустая строка                                                                       |
| `location` | `string` | непустая строка                                                                       |
| `gender`   | `string` | `male`, `female`, `genderless` или `unknown`                                          |
| `age`      | `number` | конечное число, `>= 0`                                                                |

POST и PUT требуют все поля, кроме `id`. PATCH принимает любое непустое подмножество этих полей.

## Эндпоинты

### `GET /health`

Проверка, что сервер отвечает.

Ответ `200`:

```json
{ "ok": true }
```

### `GET /characters`

Список персонажей. Поддерживаются query-параметры (можно комбинировать):

| Параметр  | Описание                                      |
| --------- | --------------------------------------------- |
| `status`  | ровно `alive`, `dead` или `unknown`           |
| `species` | фильтр по виду, сравнение без учёта регистра |

Примеры:

- `GET /characters?status=alive`
- `GET /characters?species=Human`
- `GET /characters?status=alive&species=Human`

Ответ `200`: массив объектов персонажа. Неверный `status` или пустой `species` — `400`.

### `GET /characters/stats`

Сводка по всем персонажам в хранилище (без учёта query-фильтров).

Ответ `200`:

```json
{
  "total": 2,
  "byStatus": {
    "alive": 2,
    "dead": 0,
    "unknown": 0
  }
}
```

### `POST /characters`

Создать персонажа. Сервер сам назначает `id`.

Тело запроса (все поля обязательны):

```json
{
  "name": "Summer Smith",
  "status": "alive",
  "species": "Human",
  "location": "Earth (C-137)",
  "gender": "female",
  "age": 17
}
```

Ответ `201`: созданный персонаж, включая `id`.

### `GET /characters/:id`

Один персонаж по `id`.

Ответ `200`: объект персонажа. Если такого `id` нет — `404`.

### `PUT /characters/:id`

Полная замена персонажа. `id` в URL не меняется, в теле его быть не должно.

Тело запроса (все поля обязательны):

```json
{
  "name": "Rick Sanchez",
  "status": "alive",
  "species": "Human",
  "location": "Citadel of Ricks",
  "gender": "male",
  "age": 70
}
```

Ответ `200`: обновлённый персонаж. Если такого `id` нет — `404`.

### `PATCH /characters/:id`

Частичное обновление: достаточно одного поля. Поле `id` передавать нельзя.

Тело запроса (пример — только статус и локация):

```json
{
  "status": "dead",
  "location": "unknown"
}
```

Ответ `200`: персонаж после слияния с переданными полями. Если такого `id` нет — `404`.

### `DELETE /characters/:id`

Удалить персонажа.

Ответ `204` без тела. Если такого `id` нет — `404`.

### `POST /characters/:id`

Создание по конкретному `id` не поддерживается.

Ответ `405`: `{ "error": "Method not allowed" }`.

## Ошибки

Тело ошибки: `{ "error": "..." }`.

| Код   | Когда                                                                                                  |
| ----- | ------------------------------------------------------------------------------------------------------ |
| `400` | Невалидный JSON, неполные или неверные данные персонажа, пустой PATCH, поле `id` в PATCH, неверный `status` или пустой `species` в query |
| `404` | Неизвестный путь или персонаж с таким `id` не найден                                                   |
| `405` | `POST` на `/characters/:id`                                                                            |
| `500` | Необработанная ошибка сервера                                                                          |
